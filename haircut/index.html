I. The casea publicly disclosed Bitcoin theft

The case is on Bitcoin rather than an account chain on purpose. FIFO and LIFO are orderings over unspent outputs, so on a UTXO chain they have something concrete to order. On an account-based chain you would first have to invent a balance-ordering rule, and the result would depend on that rule as much as on the theft. Everything below is derived from the transaction graph downstream of one transaction.

II. The disagreement mapbrightness shows how much the conventions disagree about an address

The tables further down answer “what does this convention say?”. This panel shows where in the population the choice of convention changes the answer. Every terminal address at the selected hop depth is plotted once. Vertical position is the value resting at that address inside this subgraph. Horizontal position is the share of that value the selected convention marks: for poison, the share it flags; for haircut, FIFO and LIFO, the share of it they attribute to the theft. Far left means none, far right means all of it. Brightness is the spread between conventions. Addresses on which every convention agrees stay dark, whether they agree on none or on all. The lit regions are where the answer depends on the convention, and the bright horizontal segments are single addresses moved from one end of the axis to the other by the ordering rule alone.

III. What the picture shows that the table does notfour shapes, recomputed from the table’s rows

The table in § IV has every number this panel displays, and its Rows: all control renders all of them. The drawing holds no extra data. The question is whether anything is easier to read as a shape. Four things are, and every figure below is recomputed in this browser from the same rows the table renders, at the hop depth and brightness measure selected above. Move the slider and these sentences change with it, including one whose conclusion reverses.

The picture is not a measurement, and nothing on this page is derived from it. Every figure comes out of data.json, and the panel is one rendering of those rows next to another. The only claim made for it is that a joint distribution over addresses has a readable shape and a sorted list of rows does not.

IV. Terminal addresseswhere value stops moving in this snapshot, all four figures side by side

A terminal address is where value from the theft transaction stops moving inside this snapshot: the output was not spent by the end of the window, it fell below the value floor, or the walk stopped at the selected hop depth. The breakdown in § VI shows how much value stops for each of those reasons. Each row carries all four figures. The poison column is flagged value, the full value of every flagged output resting there. The other three columns are the amount of the theft each conserving convention attributes to the address. An address is listed because value from the theft transaction reached it along the graph, which is a statement about transaction structure. Addresses are not people. Many of the large ones here are exchange or service wallets, and no figure in this table says who controls an address, what they knew, or that they did anything wrong. Unlabelled addresses are shown as opaque ids; § VII explains why.

V. The four conventionsthe case for each, and what it costs

Each of these is in live use, each answers a slightly different question, and each was chosen by someone who had to make a decision the data does not make for them. The figures under each card are that convention’s own output at the selected hop depth, so the cards change with the slider.

The miner fee. Satoshis paid to miners leave the graph, so a convention that ignores the fee will lose taint and appear not to balance. Here the fee is modelled as one extra synthetic output on every transaction, so inputs and outputs balance to the satoshi and taint that ends up in fees is reported as paid to miners rather than dropped. VI. The conservation gatethe check that would catch a wrong implementation, and its limits

A taint implementation that is subtly wrong still produces a plausible ranked table. The check that catches arithmetic errors is conservation: under haircut, FIFO and LIFO, every satoshi of the theft has to end up either attributed to a terminal address or paid to miners, and the two together have to equal the theft exactly. The gate below is the measured result. It was run by oracle.mjs against a second implementation of all four conventions, written separately from the one that produced this data, in a different language and with a different internal representation. Agreement between them is evidence about the arithmetic. It is not evidence about the definitions, because both follow the same specification by the same author; the note under the gate gives the example that showed this.

Where the resting value sits

Exact conservation only means something if every place value can leave the model is written down. A balanced total can hide a graph whose edges mean the wrong thing. So the terminal figure is split by why each output is resting, and the oracle requires both implementations to produce the same split and the split to add back to the terminal figure.

    VII. Methodhow the subgraph was defined, and the SQL that defined it
    
  
    The subgraph is defined in Dune SQL and the per-transaction vectors are pulled from a block explorer. Dune fixes the BFS rule, the hop assignment, the value floor and the window. The explorer supplies the ~23.8k input rows and ~7.5k output rows that the taint arithmetic needs. The BFS was then re-run against the explorer, and the two sources had to agree on transaction count, per-hop transaction count, per-hop output value, per-hop fee, row counts and distinct output addresses before the bake would run. If they had disagreed, the bake would have stopped rather than pick one.
    

  
    Subgraph definition: Dune query , execution 
    
  
    
  
    The BFS rule is in the SQL: i is every Bitcoin input in the window that spends an output of at least 0.1 BTC; b1..b5 are five self-joins outward from the seed transaction; g gives each transaction the lowest level at which it appears, which is its hop. Two choices are worth arguing with. The value floor applies to the output being followed, not to the transaction, so a small output is not followed onward but the taint that reached it is still reported as resting there. And the window truncates: an output first spent in 2020 is terminal here, which is a modelling choice, not a fact about the coin.
